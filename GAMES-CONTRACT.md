# Games implementation contract

Native Android Views/Canvas and SwiftUI/Canvas; no WebView. Shared authoritative Node rules. Existing site login exchanges its cookie for a short-lived games ticket via POST /api/games-session body `{actor:"asnat"|"youssef"}`. Response `{ticket, url}`; url is a configured wss URL, never a secret. Unconfigured service returns 503 with a helpful error. Use the existing native API request helpers.

WebSocket JSON client first sends `{type:"auth",ticket}`. Afterwards every command has UUID `id`: `list`, `create` (`game`, `settings`), `join` (`code`), `ready` (`room`, `ready` boolean), `start` (`room`), `move` (`room`, `seq`, `action`), `sync` (`room`), `rematch` (`room`), `react` (`room`, `emoji`), `ping`. Reply errors `{type:"error",id,error,code}`; acknowledgments `{type:"ack",id,seq}`. Events `{type:"welcome",actor,rooms,presence}`, `{type:"rooms",rooms,presence}`, `{type:"room",room}`, `{type:"reaction",actor,emoji,room}` and `{type:"pong",id}`. Send list to discover/resume rooms, sync after reconnect. Persist a pending move id until ack; retries reuse it. No fake peers.

Room `{id,code,game,settings,players:[{actor,ready,online}],status:"lobby"|"playing"|"finished",seq,state,scores:[0,0],result,updatedAt}`. `result` null or 0/1/"draw". Game state has `turn:0|1`, `winner:null|0|1|"draw"`. Winner checks must use explicit null, since 0 is a winner. Room code invitations open `asechka://games?code=CODE`. Game ids: pool, tictactoe, hangman, connect4, checkers, battleship.

Rules module API: export `create(settings={})`, `apply(state,player,action,settings={})`, `view(state,player)`; pure JSON state. apply returns new state or throws Error on invalid action. Common dispatcher will export createGame/applyAction/publicState and game list. Each module tests in tests/games-*.test.mjs using node:test.

States/actions:
- tictactoe: `board` 9 entries null/0/1, `line` indices. action `{type:"place",cell:0..8}`. settings bestOf 1/3/5, theme.
- connect4: `board` 42 row-major entries null/0/1, `line` indices. action `{type:"drop",column:0..6}`.
- checkers: `board` 64 entries null or `{player:0|1,king:boolean}`, `forced` null or cell, `moves` history, `legal` array `{from,to,captured?}` computed by view. action `{type:"move",from,to}`. American checkers mandatory forward captures, kings both ways, promotion ends turn; draw after 80 quiet half-moves or threefold.
- hangman: `phase:"choose"|"guess"|"finished"`, `setter:0|1`, `category`, `pattern` string (underscores), `guesses` letters, `remaining`, `hint`, optional deadline. action `{type:"word",word,category}` by setter, or `{type:"category",category}` by setter to choose a secret server word, `{type:"guess",letter}`, `{type:"hint"}`. Secret word must be removed from view except game over or setter. English categories romance,movies,animals,science,geography,food,technology,general. settings setter 0/1, timedSeconds optional. Later rematches swap setter.
- battleship: `phase:"placement"|"battle"`, `fleets` own fleet only in view (array length 2 with opponent null), `shots` arrays of cell indices per attacker, `hits` arrays of hit cell indices per attacker, `sunk` per attacker arrays of ship indices. fleet ships `{cells:[indices]}` with lengths 5,4,3,3,2 on 10x10. actions `{type:"fleet",ships:[{cells:[...]}]}`, `{type:"fire",cell}`. Opponent fleet must never be sent until legitimate sinking/game end; view can reveal sunk ship cells separately.
- pool: table coordinates 1000x500, balls radius 11, `balls:[{id,x,y,pocketed}]`, `groups:[null|"solids"|"stripes",...]`, `ballInHand` boolean, `foul` message or null, `lastShot` includes sampled `frames` of ball positions, `pocketed` ids, `firstContact`. action `{type:"shot",angle:radians,power:0..1,callPocket:0..5}` or `{type:"place",x,y}` for cue ball-in-hand. Pool module exports simulation for deterministic tests. Sampled simulation frames play locally at timestamps; final authoritative state reconciles. No streaming rendered frames.

UI includes six original cards, room lobby, actual partner presence, resume/history, share/code joining, native rules/help, sound/motion/haptics settings, rematch, error/reconnection indicators. All six boards render natively and accept real actions. Do not claim physical device tests or 60/120 FPS without measurements.
